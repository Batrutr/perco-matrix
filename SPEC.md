# Матрица доступа PERCo — техническое задание

Веб-приложение для просмотра матрицы «помещения × шаблоны доступа» системы PERCo:
дерево помещений по строкам, шаблоны доступа по столбцам, права доступа в ячейках
пересечения. С фильтрацией/подсветкой и ручным обновлением данных из API PERCo.

---

## 1. Технологический стек

| Слой | Решение |
|---|---|
| Архитектура | Локальный сервер + браузер. Сервер имеет сетевой доступ к PERCo |
| Хост PERCo | Один фиксированный, настраивается на стороне сервера (конфиг/env) |
| Бэкенд | Node.js + Fastify + TypeScript |
| HTTP к PERCo | Нативный `fetch` (Node 26) |
| Валидация ответов PERCo | `zod` |
| Кэш/хранение | SQLite (`better-sqlite3`) на сервере |
| Раздача статики | `@fastify/static` |
| Фронтенд | React + Vite + TypeScript |
| Виртуальная сетка | TanStack Virtual (виртуализация строк и столбцов) |
| Фиксация шапки/дерева | CSS `position: sticky` |
| Общие типы | Папка `shared/` с TS-типами для фронта и бэка |
| Масштаб | Сотни помещений × сотни шаблонов |

**Принцип:** всю тяжёлую работу (авторизация, N+1 запросов к PERCo, контроль
параллелизма, кэш) делает бэкенд. Браузер запрашивает у бэкенда уже агрегированную
матрицу. «Хранение на устройстве» = SQLite на сервере; обновление — вручную по кнопке.

## 2. Внешний API PERCo

Базовый адрес: `https://{host}` (host из конфига сервера).

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/api/system/auth` | Авторизация `{login, password}` → `{token}` |
| GET | `/api/rooms/tree` | Дерево помещений (рекурсивные `children`) |
| GET | `/api/accessTemplates/list` | Список шаблонов: `{id, name, comment, is_removed}` |
| GET | `/api/accessTemplates/{id}` | Детали шаблона с массивом `access[]` |

**Авторизация:** токен передаётся в заголовке `Authorization: Bearer <token>`.
Токен (ключ) имеет «скользящий» срок жизни — протухает при простое (idle timeout),
после чего любой запрос отдаёт `401`. Фиксированного TTL нет, поэтому стратегия —
**ленивый релогин по `401`**: ловим `401` → авторизуемся заново → повторяем исходный
запрос (один раз). Проактивное обновление токена по таймеру не требуется.

**Структура узла дерева (`/api/rooms/tree`):**
`id, is_const, name, parent_id, node_type ("room"), segment_id, with_rights, room_id, children[]`

**Структура ячейки (`access[]` в `/api/accessTemplates/{id}`):**
`access_zone_id` (= id помещения/зоны), `template_type`, `rights{...}`.
Ячейка матрицы (помещение × шаблон) заполнена, только если в шаблоне есть `access`
с `access_zone_id`, совпадающим с `room_id` помещения.

**Значимые поля прав (приоритет отображения):** `schedule_type{id,name}`,
`schedule{id,name}`, `is_guard`, `is_antipass`. Остальные поля сохраняем в кэш на будущее.

## 3. Внутренний API (бэкенд → фронтенд)

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/state/rooms` | Дерево помещений из кэша |
| GET | `/api/state/templates` | Список шаблонов из кэша |
| GET | `/api/state/matrix` | Агрегированная матрица: ячейки {template_id, room_id, rights} |
| GET | `/api/state/meta` | Время последнего обновления каждого типа, статус |
| POST | `/api/refresh/rooms` | Перезапросить дерево помещений из PERCo |
| POST | `/api/refresh/templates` | Перезапросить все шаблоны (list + N деталей) |
| POST | `/api/refresh/all` | Обновить и помещения, и шаблоны |
| GET | `/api/refresh/status` | Прогресс текущего обновления (SSE или polling) |

## 4. Схема SQLite

```
rooms(
  id INTEGER PK, parent_id INTEGER, name TEXT, room_id INTEGER,
  node_type TEXT, is_const INTEGER, with_rights INTEGER,
  depth INTEGER, sort_order INTEGER
)

templates(
  id INTEGER PK, name TEXT, comment TEXT, is_removed INTEGER, fetched_at TEXT
)

template_access(
  template_id INTEGER, access_zone_id INTEGER, template_type INTEGER,
  is_guard INTEGER, is_antipass INTEGER, is_verify INTEGER,
  schedule_type_id INTEGER, schedule_type_name TEXT,
  schedule_id INTEGER, schedule_name TEXT,
  raw_json TEXT,
  PRIMARY KEY (template_id, access_zone_id)
)

meta(key TEXT PK, value TEXT)
  -- last_update_rooms, last_update_templates, refresh_status, token, token_expiry
```

## 5. Функциональные требования (UI)

### Матрица
- [ ] Строки — помещения (плоский список из дерева), столбцы — шаблоны.
- [ ] Первый столбец (дерево помещений) зафиксирован при горизонтальном скролле.
- [ ] Шапка (названия шаблонов) зафиксирована при вертикальном скролле.
- [ ] Виртуализация строк И столбцов (сотни × сотни).
- [ ] При наведении/скролле видны: название шаблона, название помещения и значение ячейки
      (подсветка активной строки/столбца, либо «липкая» подпись).

### Дерево помещений
- [ ] Отображение иерархии (`parent_id`/`children`) с отступами по уровню.
- [ ] Сворачивание/разворачивание узлов; свёрнутые скрывают строки-потомки в матрице.
- [ ] Состояние раскрытия дерева сохраняется (localStorage).

### Ячейка пересечения
- [ ] Показывает права шаблона в помещение: `schedule_type`, `schedule`, `is_guard`, `is_antipass`.
- [ ] Пустая ячейка — доступа нет.
- [ ] Компактное отображение + подробности по наведению/клику (tooltip/popover).

### Фильтрация и подсветка
- [ ] Фильтр/подсветка шаблонов по значению в ячейках.
- [ ] Фильтр/подсветка помещений по значению в ячейках.
- [ ] Критерии: наличие доступа, конкретный `schedule`/`schedule_type`, `is_guard`, `is_antipass`.
- [ ] Режим «скрыть» vs «подсветить».

### Доступ к интерфейсу
- [ ] Простая парольная защита самого веб-интерфейса (одна общая пароль-фраза).
      Желательна, но не критична — сервер в доверенной сети.

### Обновление данных
- [ ] Кнопка «Обновить помещения».
- [ ] Кнопка «Обновить шаблоны».
- [ ] Кнопка «Обновить всё».
- [ ] Индикатор прогресса при N+1 загрузке шаблонов.
- [ ] Отображение времени последнего обновления каждого типа.
- [ ] Корректная обработка и показ ошибок (сеть, авторизация, частичный сбой).

## 7. Решённые вопросы

- **Авторизация PERCo:** заголовок `Authorization: Bearer <token>`.
- **Срок жизни токена:** скользящий, протухает при простое → `401`. Стратегия —
  ленивый релогин по `401` (без таймеров).
- **Пустые `name` помещений:** на практике не встречаются (в примере были для иллюстрации);
  fallback не требуется.
- **Деплой:** systemd-юнит и/или Docker.
- **Защита веб-интерфейса:** простая парольная защита; желательна, но не критична.
