# Бэклог фич

Комментарии к версии, развёрнутой в `/opt` (baseline). Пункты 4–5 уже реализованы
в версии со счётчиками; остальное — к реализации.

## Реализовано (версия со счётчиками)

- [x] Учёт «популярности» шаблона — скольким сотрудникам он назначен
      (`employeeCount`, `SELECT` к `user_access_template` в БД PERCo).
- [x] Учёт «насыщенности» шаблона — сколько в нём критериев доступа
      (`roomCount`, число зон в кэше `template_access`).
- [x] Отдельная быстрая кнопка обновления числа сотрудников; читаемые счётчики
      (две ячейки-строки в шапке столбца).
- [x] Поиск по названию шаблона.
- [x] Поиск по помещению.
- [x] Сортировка шаблонов: по имени, по числу помещений, по числу сотрудников.

## К реализации

- [ ] Контекстное меню по клику на шаблон: скрыть в дереве помещения, у которых нет
      критериев в этом шаблоне или наоборот есть критерии в этом шаблоне.
- [ ] Контекстное меню по клику на помещение: скрыть шаблоны, в которых нет критериев
      для этого помещения или наоборот есть критерии для этого помещения.
- [ ] Кнопки показа ранее скрытых шаблонов и помещений.
- [ ] Закрепление (pin) шаблонов в левой части независимо от сортировки, со sticky-
      фиксацией при горизонтальной прокрутке.
- [ ] Возможность выбрать помещения, и в пустом столбце (пустой/новый шаблон) указать нужные отметки (антипас, охрана, график), и по ним должен найти один или несколько шаблонов, которые смогут реализовать данную функцию

## Известные проблемы (вернуться)

- [ ] **Число сотрудников теряется при рестарте/перезагрузке сервера.** Остальные
      данные (помещения, шаблоны, доступы) сохраняются, а `employee_count` приходится
      обновлять заново.
      Вероятная причина: большие записи (помещения, ~десятки тысяч строк доступа)
      провоцируют авто-checkpoint и попадают в основной файл SQLite, а небольшой
      `UPDATE employee_count` остаётся только в WAL; при негладком завершении/перезагрузке
      несинхронизированный WAL теряется (по умолчанию `synchronous=NORMAL` в WAL-режиме).
      Возможный фикс: `PRAGMA synchronous = FULL` и/или явный `wal_checkpoint(TRUNCATE)`
      после обновления + graceful shutdown (checkpoint + `db.close()` по SIGTERM).
      Перед фиксом — детерминированно воспроизвести (скрипт уже набросан).
