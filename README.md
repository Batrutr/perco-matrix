# Матрица доступа PERCo

Одностраничное веб-приложение: матрица «помещения × шаблоны доступа» системы PERCo.
Строки — дерево помещений (сворачиваемое), столбцы — шаблоны доступа, в ячейках — права
доступа шаблона в помещение. Поиск и сортировка, фильтр/подсветка по значениям, скрытие
лишнего через контекстное меню, закрепление важных шаблонов, подбор шаблона по
требованию, светлая/тёмная тема. Данные — ручным обновлением из API PERCo.

## Архитектура

Локальный сервер (Node.js + Fastify) на машине с доступом к PERCo:
- хранит учётные данные PERCo и ходит к его API (обход CORS, секреты не уходят в браузер);
- по кнопке выкачивает данные (N+1 с контролем параллелизма и ретраями) и кэширует в SQLite;
- отдаёт браузеру готовую агрегированную матрицу и раздаёт собранный фронтенд.

Стек: **Fastify + node:sqlite** (бэкенд), **React + Vite + TanStack Virtual** (фронтенд),
общие типы в `shared/`. Требуется **Node.js ≥ 22** (рекомендуется 24+: встроенный
`node:sqlite` без флага).

```
shared/   общие TS-типы (контракт фронт↔бэк)
server/   Fastify: PERCo-клиент, кэш SQLite, внутренний API, безопасность
client/   React-SPA: виртуализированная матрица, фильтры, подбор, темы
deploy/   systemd-юнит
```

## Настройка

```bash
cp .env.example .env
```

Основные переменные (полный список — в [.env.example](.env.example)):

| Переменная | Назначение |
|---|---|
| `PERCO_HOST` | Адрес сервера PERCo (`https://…`) |
| `PERCO_LOGIN` / `PERCO_PASSWORD` | Учётные данные PERCo |
| `PERCO_CONCURRENCY` | Параллелизм загрузки шаблонов (по умолчанию 8) |
| `PERCO_TLS_REJECT_UNAUTHORIZED` | Проверять TLS PERCo. `false` — только для self-signed в доверенной сети |
| `PORT` / `HOST` | Где слушает приложение |
| `DB_PATH` | Файл SQLite-кэша |
| `PINNED_TEMPLATES` | «Важные» шаблоны для кнопки закрепления (id или имена через запятую) |
| `SCHEDULE_ABBR` | Аббревиатуры графиков для ячеек: JSON «имя → буква» (пусто = первая буква) |
| `APP_PASSWORD` | Пароль на интерфейс (пусто = без защиты) |
| `APP_COOKIE_SECRET` | Секрет cookie-сессии (по умолчанию выводится из пароля) |
| `PERCO_DB_HOST` … | БД PERCo (MariaDB) для счётчика сотрудников на шаблон. Пусто = счётчик «–». Рекомендуется отдельный пользователь с правом только на `SELECT` |

В шапке каждого столбца-шаблона показаны два счётчика: <span style="color:#2e7d32">**помещений**</span>
(сколько зон охватывает шаблон, из кэша) и <span style="color:#1565c0">**сотрудников**</span>
(сколько пользователей ему назначено — `SELECT` к `user_access_template` в БД PERCo).

## Разработка

```bash
npm install
npm run dev     # Fastify :3000 + Vite :5173 (проксирует /api). Откройте http://localhost:5173
```

Без реального PERCo можно засеять синтетические данные «сотни × сотни»:

```bash
DB_PATH=./data/dev.sqlite npm run seed --workspace server
DB_PATH=./data/dev.sqlite npm run dev
```

Проверки:

```bash
npm run typecheck                 # типы всех воркспейсов
npm run test --workspace server   # тесты бэкенда
npm run test --workspace client   # тесты фронтенда (матрица/фильтры/подбор/сортировка)
```

## Прод-сборка и запуск (без Docker)

```bash
npm ci
npm run build           # shared (типы) → client (Vite) → server (esbuild-бандл)
npm start               # node server/dist/index.js — раздаёт client/dist и API
```

### systemd

См. инструкцию в шапке [deploy/perco-matrix.service](deploy/perco-matrix.service):
разместить репозиторий в `/opt/perco-matrix`, создать `.env`, скопировать юнит,
`systemctl enable --now perco-matrix`.

## Деплой через Docker

```bash
docker compose up -d --build
```

Контейнер слушает `:3000`, читает `.env`, хранит SQLite в volume `perco-data`.
Образ многостадийный, рантайм — только прод-зависимости и собранные бандлы.

## Использование

1. Откройте приложение (при заданном `APP_PASSWORD` — введите пароль).
2. Кнопками **«Обновить помещения / шаблоны / сотрудников / всё»** загрузите данные
   из PERCo (виден прогресс N+1; данные кэшируются на сервере).
3. **Дерево помещений.** Сворачивайте узлы кликом по строке; кнопки «Дерево: свернуть
   всё / до ур. N / развернуть всё» быстро сворачивают на нужную глубину. Длинные
   названия видны во всплывающей подсказке.
4. **Поиск и сортировка.** Поиск по имени шаблона и помещения; сортировка шаблонов
   (имя / число помещений / сотрудников) и помещений (по имени или «как в PERCo» — с
   сохранением дерева).
5. **Фильтр по значениям** (график / охрана / antipass): режим «подсветка» приглушает
   несовпавшее, режим «скрытие» убирает несовпавшие строки/столбцы.
6. **Скрытие через контекстное меню** (ПКМ по шаблону или помещению): скрыть помещения
   или шаблоны по критерию «с доступом / без доступа». При нескольких скрытиях —
   переключатель совмещения «∩ во всех / ∪ в любом»; «Показать всё скрытое» сбрасывает.
7. **Закрепление шаблонов** слева (ПКМ → «Закрепить», sticky при прокрутке). Кнопка
   «Закрепить важные» закрепляет шаблоны из `PINNED_TEMPLATES`.
8. **Подбор шаблона по требованию** (кнопка «🔍 Подбор шаблона»): отметьте нужные
   помещения и требуемые отметки в столбце «Требование» — приложение покажет шаблоны,
   целиком покрывающие требование, либо их минимальную комбинацию (жадный set-cover) и
   непокрытые помещения.
9. **Тема** — кнопка переключения: светлая / тёмная / как в системе.
10. Наведение на ячейку показывает шаблон, помещение и права (график, охрана, antipass)
    в нижней панели и во всплывающей подсказке.

## Безопасность

Парольная защита (cookie-сессия, rate-limit логина), security-заголовки (helmet),
закрытый CORS, лимит размера тела, rate-limit обновления, фиксированный хост PERCo
(без open-proxy/SSRF), параметризованные SQL-запросы.
